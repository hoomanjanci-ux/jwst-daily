# خط لولهٔ صفر-هزینهٔ JWST → تلگرام (نسخهٔ آمادهٔ اجرا)

این بسته، خروجی عملی مرحلهٔ «نمونه‌سازی» مأموریت نسخهٔ ۲ است: کد کامل، آمادهٔ push به یک مخزن عمومی GitHub.

## ساختار
```
.github/workflows/jwst-daily.yml   # زمان‌بند روزانهٔ GitHub Actions (عمومی = رایگان)
pipeline/
  mast_discover.py    # کشف محصولات عمومی JWST روی MAST (astroquery، بدون احراز هویت)
  fits2png.py         # دسته‌بندی HDU + متادیتا + رندر PNG (ZScale+asinh) + رابط mock تحلیل
  telegram_publish.py # انتشار به ۴ کانال + مدیریت 429 + backoff + سقف کپشن 1024
  run_daily.py        # ارکستراتور روزانه: بودجهٔ بایت، dedup با state.json، پاکسازی فایل موقت
  state.json          # دفتر کل انتشارها (به مخزن commit می‌شود؛ جایگزین دیتابیس)
requirements.txt
```

## راه‌اندازی (اقدامات کاربر — عامل به حساب‌ها دسترسی ندارد)
1. مخزن **عمومی** جدید در GitHub بسازید و این پوشه را push کنید.
2. در Settings → Secrets and variables → Actions پنج Secret بسازید:
   - `TG_BOT_TOKEN` توکن بات
   - `TG_CH_FA_AI` ، `TG_CH_EN_AI` ، `TG_CH_FA_OFF` ، `TG_CH_EN_OFF` (آیدی عددی یا @کانال‌ها؛ بات باید ادمین هر چهار کانال باشد)
3. اولین اجرا را دستی بزنید: تب Actions → jwst-daily → Run workflow (بهتر است اول با `MAX_BYTES` کوچک تست کنید).
4. بعد از تأیید موفقیت، زمان‌بند روزانه خودش ادامه می‌دهد.

## نکته‌های مهم
- **نگه‌داشتن زمان‌بند زنده**: ورک‌فلوهای schedule بعد از ۶۰ روز بی‌فعالیتی مخزن غیرفعال می‌شوند. خودِ commit روزانهٔ `state.json` مخزن را فعال نگه می‌دارد؛ به‌عنوان پشتیبان، یک ورک‌فلو keepalive کوچک هم می‌توان افزود.
- **mock**: تا وقتی Vision API کاربر متصل نشده، متن تحلیل با `"mock": true` تولید می‌شود و نباید به‌عنوان تحلیل علمی واقعی منتشر شود.
- **۵GB/day**: `MAX_BYTES` را بالا ببرید و در صورت نیاز با matrix jobs موازی‌سازی کنید (چک‌لیست کامل در گزارش).
- فایل خام FITS بعد از استخراج PNG حذف می‌شود؛ نگهداری دائمی لازم ندارد (طبق مأموریت).
